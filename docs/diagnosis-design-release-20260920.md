# PWA 1.0.77 / Android Beta 1.16 통합 릴리스

2026-09-20. 사용자가 디자인 보완과 진단 수정의 통합 배포를 승인했다. 이번 묶음은 앞선 진단의 우선 수정분이며 원문 65건 전체 해결을 뜻하지 않는다.

## 변경

- PWA 1.0.76의 기존 디자인·시작 화면을 보존하고 저장 실패/충돌 안내를 공통 글자 체계에 맞췄다. 기록 수정 링크의 44px 터치 영역과 화살표를 복구했다.
- Android는 구역 코드별 색 유지와 최신 진단 수정을 보존하며 카드·글자·여백·터치 크기를 정리한다. 순번 기반 3색 명도 순환은 적용하지 않는다.
- 근무표 재반영 시 입력 건수·단가를 보존하고, 서로 다른 구역의 100/60을 균등 재분배하지 않는다. 미저장 초안과 저장 실패 중에는 서버 재조회가 입력을 덮지 못한다.
- 수동 기록은 서버 변경 시각을 비교해 충돌을 표시한다. 서버 기록을 선택할 때 입력을 세션 내 별도 보관하며 복사 안내를 제공한다. 이 보관본은 영구 저장이 아니다.
- OCR 묶음 구역·연도 경계·미인식 처리를 보완하고 승인·요청 크기·동시성·사용량 제한을 적용한다. 고정 기사도 미인식을 자동으로 고정 구역에 배정하지 않는다.
- XLSX/ZIP 브라우저 로드, 날짜·한국어 서식·기간별 조정 집계, 날짜 없는 지출 초안의 휴지통 조회를 수정한다. 지출 원금을 누적 환불보다 낮게 저장할 수 없다.
- 비밀번호 복구 이벤트 처리, 승인 상태 재확인, 과거 점검표 재서명 확인, 캘린더 비활성 작업 종료를 보완했다. Supabase SDK는 동일 출처의 2.116.0으로 고정한다.

## 서버 배포 결과

- 프로젝트: `xrrdokcjhjqdfvwtbenl`.
- 적용 migration: `20260920012920_ocr_quota_and_expense_refund_guard.sql`. 개발 시 20260919083335 이름으로 만든 동일 SQL을 지정 적용하고 운영에서 기록된 version에 맞춰 로컬 파일명을 정렬했다. 과거 migration 전체를 재적용하지 않았다.
- OCR `ocr-schedule` v35 ACTIVE, `verify_jwt=true` 유지.
- Calendar `calendar-sync` v6 ACTIVE, 기존 자체 인증/OAuth callback/cron 계약에 맞춰 `verify_jwt=false` 유지.
- 실제 DB에서 새 RPC의 익명 실행 금지, authenticated 실행 권한, private quota 두 테이블 RLS·직접 접근 금지 확인. 비인증 OCR quota/수동 저장 거절은 rollback 트랜잭션으로 확인했으며 운영 업무 데이터를 추가하지 않았다.
- HTTP OPTIONS 200, 비인증 POST는 OCR·Calendar 모두 401.
- 보안 advisor 신규 WARN 0. 서버 전용 quota 테이블 두 개의 RLS/no-policy INFO는 클라이언트 접근을 막는 의도된 상태다. 기존 타 기능의 경고는 이번 수정 범위 밖이다. [RLS 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)

## 검증 범위

- PWA 전체 Node 테스트 308/308 통과(실패·생략 0), first-party JavaScript 40파일 구문 검사 통과. 삭제 응답 대기 중 새 입력/초안 보존 4개 회귀 사례를 추가했다.
- 360px/900px 다크·라이트에서 실제 스타일/마크업을 사용한 합성 fixture로 저장 안내·수정 링크·44px 터치 영역·키보드·가로 넘침을 확인했다. 실제 정적 index도 로그아웃 상태의 로그인 화면 초기화까지 확인했다.
- Android 전체 테스트·컴파일·스크린샷·릴리스 APK 검증 결과는 Android 저장소의 `docs/beta-1.16-release.md`를 기준으로 한다.
- 실제 사용자 로그인·유료 OCR 이미지·Google 일정 쓰기·휴대전화 설치는 이번 배포 검증에서 수행하지 않는다. Deno 타입검사 환경은 없었으며 서버 소스 구문 검사와 배포 번들 생성을 확인했다.

## 남은 범위

동일 업무의 수기 대체/늦은 자동 전송 연결, 회수 근거 개별 편집, 영수증 고아 파일 재처리, Google 계정 변경 전체 흐름, 계정 삭제 운영 절차 등은 후속 항목이다. 새 수동 저장 충돌 보호는 새 checked RPC를 쓰는 클라이언트에 적용되며 구버전 쓰기까지 revision을 강제하는 변경은 아니다. 현장 중복 송장·136/134 보고의 원인을 이번 변경으로 확정하지 않는다.

## 배포 순서

DB 지정 migration → OCR/Calendar 함수 → 검증된 Beta 1.16 APK 게시 → APK 링크가 포함된 PWA 1.0.77 게시 → 운영 버전·정적 파일·릴리스 파일 확인.
