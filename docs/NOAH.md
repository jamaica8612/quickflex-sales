# 노아

플렉스노트의 로그인한 사용자용 AI입니다. Supabase Edge Function `noah`에서 OpenAI Responses API를 호출합니다. 기본 모델은 `NOAH_MODEL`(기본 `gpt-6-luna`)이며, 짧은 인사와 한 번의 정산 조회로 끝나는 질문에는 `NOAH_MODEL_FAST`를 선택적으로 사용할 수 있습니다. `OPENAI_API_KEY`는 Edge Function Secret에만 등록합니다.

## 답변 형식

- 지시문의 `NOAH_ANSWER_STYLE`(`supabase/functions/noah/handler.js`)이 답의 뼈대를 정합니다. 첫 줄은 결론이나 확인된 핵심 숫자이고, 개인 기록을 조회한 답은 근거 2~3개, 해석 한 줄, 다음 제안 하나를 붙여 보통 3~6줄로 씁니다. 인사·예/아니오·화면 위치 안내는 한두 줄로 끝냅니다.
- 매출·정산 요약, 목표 분석, 지출 분석, 구역·배송 팁, 기간 비교의 유형별 틀과 형식 예시가 있습니다. 예시 숫자는 실제 자료가 아니므로 답에 옮기지 않도록 지시하고, 조회한 자료에 없는 수치나 원인은 만들지 않습니다.
- `NOAH_VERBOSITY`(`low`·`medium`·`high`)를 Edge Function Secret으로 설정하면 Responses API 요청에 `text.verbosity`를 넣습니다. 설정하지 않거나 다른 값이면 보내지 않습니다. 모델이 이 옵션을 지원하는지 확인한 뒤 켭니다.

## 조회와 변경

- 본인의 매출·배송 완료 기록, 날짜별 수정, 단가, 지출·환불·재입금, 일상 점검, 프로필과 소속 회사의 구역·배송 팁·즐겨찾기를 조회합니다. 사용자 JWT, 승인 상태, 명시적 소유자 조건과 기존 RLS를 함께 적용합니다.
- 정산 요약은 앱과 같은 계산 규칙으로 서버에서 집계합니다. 월 정산은 전월 26일~해당 월 25일입니다. 불완전한 원장이나 조회 실패를 전체 합계로 표시하지 않습니다.
- 근무일 안내는 요청마다 서버가 본인 프로필의 주간/야간 설정과 한국 날짜의 일자 기록, 실제 구역 항목, 자동 마감, 유효한 진행 중 작업을 읽어 계산합니다. 고정 구역 설정은 오늘의 실제 일정으로 간주하지 않습니다. 브라우저가 보낸 날짜·근무 상태는 근거로 사용하지 않습니다.
- 진행 중인 작업이 있으면 그 근무일을 실효 업무일로 우선합니다. 야간 근무에서는 오늘 자동 마감, 명시적 휴무, 오늘 일정과 자동 마감이 모두 없는 경우 순으로 다음 업무일을 판단합니다. 실제 일정이 있고 자동 마감이 없으면 오늘을 사용합니다. 조회 실패로 근거가 불명확하면 한국시간 정오(12시) 전에는 오늘, 이후에는 내일로 추정하며, 일정 없음으로 단정하지 않습니다. 주간 근무의 직전·다음·실효 업무일은 모두 오늘입니다.
- 완료한 배송·매출은 직전 업무일, 예정 구역·배송 팁·준비는 다음 업무일을 기본 기준으로 사용합니다. 야간의 직전 업무일은 다음 업무일의 달력상 하루 전이며 가장 최근 매출 기록을 검색한 날짜가 아닙니다. 날짜가 다르고 질문의 뜻이 불명확하면 어느 날짜인지 묻고, 날짜 의존 답변에는 기준일을 짧게 표시합니다. 사용자가 날짜를 명시하면 그 날짜를 따릅니다.
- 지출 추가·수정·휴지통 이동, 월 매출 목표, 구역 현재 단가 변경을 제안할 수 있습니다. 자동 배송 원장, 과거 단가 스냅샷, 계정 권한은 변경하지 않습니다.
- AI에는 변경을 실행하는 도구가 없습니다. 서버에 저장된 10분 유효 제안의 이전/변경 값을 보여 준 뒤 사용자가 **확인 후 적용**을 눌러야 반영됩니다. 대화로 “응”이라고 답해도 실행하지 않습니다.
- 확인 RPC는 소유자·승인·만료·기존 값 변경을 다시 검사하고 하나의 트랜잭션으로 적용합니다. 같은 제안을 재확인해도 중복 실행하지 않습니다. 취소는 업무 데이터를 변경하지 않습니다.

## 화면

- 내 말풍선은 강조색으로 채우고, 노아 말풍선은 테두리가 있는 카드로 보여 줍니다. 입력창은 하단 메뉴 바로 위에 붙은 입력 바 안에 있으며, 키보드가 올라오면 `visualViewport` 높이에 맞춰 화면을 줄이고 하단 메뉴를 잠깐 숨깁니다(`src/ui/noah-keyboard.js`).
- 질문을 보내면 노아 자리에 **생각 말풍선**이 뜨고, 서버가 보내는 `progress` 이벤트만 단계로 쌓습니다. 앞으로의 단계를 미리 꾸며 보여 주지 않습니다. 첫 답 글자가 오면 `매출 기록 확인함 · 2.1초` 같은 접힌 요약으로 바뀌고 눌러서 단계를 다시 볼 수 있습니다(`src/lib/noah-thinking.js`). 스트리밍이 아닌 응답에서는 단계 없이 `생각 완료`만 표시합니다.
- 안드로이드 앱의 당겨서 새로고침(SwipeRefreshLayout)은 웹 페이지가 맨 위일 때 시작합니다. 노아 화면은 대화창 안쪽만 스크롤해 페이지가 늘 맨 위이므로, 앱 안(`QuickFlexNative` 또는 `QuickFlexMerged/` UA)에서 노아 화면일 때만 페이지를 1px 내려 둡니다(`src/ui/noah-refresh-guard.js`). 브라우저·iOS PWA는 영향이 없습니다. 근본 해결은 앱이 PWA의 화면 정보를 받아 노아에서 새로고침을 끄는 것이며, 안드로이드 최신 소스가 필요합니다.
- 생각하는 동안 추천 질문은 숨기고, 진행 문구는 화면 읽기용 상태 영역에만 남깁니다. `새 대화`는 제목 옆 설정 버튼 왼쪽에 있습니다.

## 데이터와 운영

질문에 필요한 본인 기록과 소속 회사 구역 팁(작성자 이름 포함)은 OpenAI로 전달됩니다. Responses API에는 `store: false`를 설정합니다. 노아 대화 원문은 서버에도 기기에도 저장하지 않습니다. 대화는 현재 화면 메모리에만 있고, 앱을 닫거나 새 대화·로그아웃·계정 전환·계정 상태 초기화·탈퇴 요청 때 사라집니다. 서버에는 확인 전 변경 제안(10분 유효)과 사용량, 첫 사용 안내 확인 시각만 저장합니다.

1.0.95~1.0.96은 기기에 최근 대화를 보관했습니다. 1.0.97부터 앱 시작 때 `src/lib/noah-legacy-storage.js`가 IndexedDB `quickflex-noah-local`과 localStorage의 `quickflex-noah:` 키를 지웁니다. 1.0.96 이하 설치가 더 이상 쓰이지 않으면 이 정리 코드를 지워도 됩니다.

노아는 존댓말로 옆자리 동료처럼 짧게 답하고 첫 문장에 결론을 말합니다. 숫자를 먼저 말하고 설명은 한두 줄로 하며, 인사는 대화의 시작이나 끝에 한 번만 씁니다. 답변에는 이모지와 과장된 칭찬을 넣지 않습니다. 기록이 없으면 솔직히 말하고 입력 화면을 안내하며, 변경을 제안할 때는 “이렇게 바꿔 둘까요? 아래에서 확인을 눌러 주세요.”라고 묻습니다.

AI 요청은 사용자별 분당 10회, 한국 날짜 기준 하루 100회로 제한합니다. 도구 호출·문맥·출력·응답 시간에도 상한이 있습니다. 확인과 취소는 AI 사용량 제한과 별개입니다.

1.0.97 배포 순서는 새 `20260924120000_remove_noah_feedback.sql` 마이그레이션만 적용(답변 평가 테이블과 함수 삭제, 저장된 평가도 삭제) → `noah` 함수 배포 → PWA 1.0.97 배포입니다. 안내 확인과 사용량 제한(`20260924081941`)은 그대로 둡니다. 공유 Supabase 프로젝트의 다른 마이그레이션이나 함수는 함께 배포하지 않습니다. JWT 검증을 유지하고 `noah/index.ts`에서 사용자와 승인 상태를 추가 검증합니다.

탭을 열면 첫 사용 안내(한 번), 업무 상황에 맞는 인사와 추천 질문 3개를 보여 줍니다. 브리핑 카드와 답변 평가는 1.0.97에서 없앴습니다. 답변은 진행 상태와 최종 문장을 SSE로 보내고, 스트림이 실패하면 기존 JSON 응답으로 재시도합니다. 답변 바로 아래에는 실제로 조회한 날짜·구역·지출·정산·설정으로 이동하는 링크가 표시됩니다.

로컬 회귀 검증은 `node --test tests/noah-*.test.mjs`입니다. SQL 테스트는 격리된 PGlite DB에서 실제 기존 지출 RPC와 새 마이그레이션을 실행합니다. `tests/fixtures/noah.html`은 실제 계정에 연결하지 않는 화면 검증용 모의 응답입니다.

## 운영자 확인 필요

공개 페이지에서 내부 메모를 뺀 대신 아래 항목을 여기서 관리합니다.

- OpenAI의 실제 계약·데이터 레지던시 설정에 따른 처리 국가와 보관 기간, 국외 이전의 법적 근거와 처리위탁·제3자 제공 구분, 이전받는 법인·연락처, 이전 시점·방법과 거부 방법·영향을 확인해 `privacy.html` 4항에 반영합니다.
- 만료된 노아 변경 제안의 보관 기간과 정기 삭제 정책을 정합니다.
