# 회사 구역노트

이번 배포는 PWA 1.0.86이며 Android는 Beta 1.20을 유지한다. 밝은 화면 고정·팁 단독 표시·전체 화면·지도 공유 버튼 및 일반 회원 구역 생성/작성자 삭제를 포함한다. 사용자 배포 승인에 따라 `20260921224120_route_note_member_zones.sql`을 운영 DB에 먼저 적용했다. 로컬 마이그레이션 파일명은 서버가 기록한 버전과 맞췄다. APK 재설치 없이 PWA 갱신으로 새 화면을 사용할 수 있다.

## 이번 범위

- 하단 메뉴: 매출 / 배송 / 구역 / 지출 / 더보기. 화면명은 매출노트·배송노트·구역노트·지출노트로 맞추고, 통계는 더보기에서 연다.
- 구역노트 첫 화면은 검색 가능한 구역 목록이다. 하나를 선택하면 그 구역의 경계와 팁만 지도에 표시한다. 검색창과 전체·즐겨찾기·내 구역 필터는 유지하고, 메모 검색은 현재 열린 구역의 팁까지 찾는다. 회사 전체 팁을 한 번에 내려받지 않는다. `구역 만들기`는 목록에 있고, `공유`와 `내 위치`는 선택한 구역의 지도 오른쪽에 있다.
- 지도 마커나 메모 검색 결과를 누르면 선택한 팁과 그 사진·작성자만 연다. `전체 메모 보기`로 그 구역의 팁 목록으로 돌아간다. 작은 화면의 시트는 손잡이를 끌거나 짧게 눌러 접힘·절반·최대 세 단계로 조절하고(키보드는 ↑↓), 넓은 화면은 우측 패널이다. 네이버 기본 확대/축소 버튼은 숨기고 지도 터치 제스처는 유지한다.
- 검색창 오른쪽 `전체 화면 보기`는 하단 앱 메뉴를 숨기고 구역노트를 화면 전체에 펼친다. 선택된 구역은 우선 지도만 크게 보이며 `메모 보기`로 시트를 연다. 닫기 버튼이나 Android 뒤로가기로 복귀한다. 팁 작성 중 위치 선택과 전체 화면 종료는 작성 중인 입력을 유지한다.
- 구역노트와 공유 대화상자는 앱 테마와 관계없이 밝게 표시한다. 지도·메모에 같은 SVG 아이콘을 쓰고 구역 경계는 선택 2px/비선택 1px, 낮은 채움 불투명도로 표시한다.
- 승인된 회사 회원은 회사 전체 구역과 팁을 읽고 개인 즐겨찾기를 저장한다.
- 회원 누구나 구역 공통 팁과 위치별 배송 팁을 작성한다. 공통 팁은 위치 없이 설명·사진을 남기며, 위치별 팁은 지도에서 구역 경계 안을 누르거나 길게 눌러 `팁 등록하기`로 시작한다. 경계선은 허용하고 내부 빈 영역은 제외한다. 좌표 직접 입력은 팁 화면에 노출하지 않는다.
- 팁·사진 수정/삭제는 작성자 본인만 가능하다. 관리자도 다른 작성자의 팁을 수정하지 못한다.
- 팁에 작성 당시 프로필 이름을 서버에서 기록해 표시한다. 다른 회원의 프로필 테이블은 공개하지 않는다.
- 승인된 회사 회원 누구나 구역을 만든다. 작성자와 기존 관리자/편집자는 구역을 수정하며, 삭제는 작성자 본인만 가능하다. 팁이나 구역 참고 사진이 남아 있으면 삭제를 막고 각 작성자가 먼저 정리해야 한다. 작성자를 확인할 수 없는 이관 구역을 일반 회원에게 임의로 귀속하지 않는다. 새 구역은 우편번호 경계 또는 직접 그린 경계를 하나 이상 추가한 뒤 저장한다. 기존 경계 없는 이관 구역의 메모·사진은 보존한다.
- 중복 구역은 회사 안에서 이름의 대소문자·공백·전각 문자를 정규화해 막는다. 예를 들어 `303a`, `303 A`, `３０３Ａ`는 같은 이름이다. 화면 검사에 더해 DB 고유 인덱스로 동시 생성·이름 변경도 검사한다. 기존 중복을 자동 병합하거나 삭제하지 않는다.
- 달력에서 선택한 날짜의 구역노트로 이동한다. 매출·지출·측정 기록과는 별도 데이터다.
- 승인된 고정기사의 `fixed_routes`와 구역 이름에 명시된 코드를 정확히 비교해, 매칭이 있으면 `내 구역`을 먼저 연다. 전체 구역·즐겨찾기·검색창은 유지한다. `303A302B`는 `303A`와 `302B`이며 근처 코드로 추측하지 않는다.
- 코멘트·실시간 위치 공유·자동 위치 추적은 포함하지 않는다. 지도에서 사용자가 누르는 `내 위치` 단발 조회와 팁 좌표는 유지한다.
- 기간제 외부 공유 링크를 구현한다. 로그인 없는 구역별 읽기, 1~30일 기간 설정, 생성자 본인의 중지·연장을 지원한다. 사용자가 이번에는 링크 만료 후 영구 저장을 제외하도록 선택했다.
- 개인 복사본 저장, 기존 RouteNote의 특수 시장 화면·동선·로드뷰는 이번 기능 범위 밖이다.

## 구조와 적용 준비

`src/ui/route-notes.js`는 기존 PWA 로그인 세션을 사용하며, 별도 RouteNote 로그인이나 iframe을 열지 않는다. `src/services/route-notes.js`가 회사 멤버십을 확인하고 모든 질의를 회사별로 제한한다. API·사진·업무 데이터를 브라우저 로컬 저장소에 보관하지 않는다.

`supabase/migrations/20260921110850_company_route_notes.sql`과 `20260921110900_route_note_import_provenance.sql`은 회사 구역노트 테이블·권한·private 사진 저장소·원본 보관 구조를 추가한다. 두 DB 변경과 데이터·사진 복사는 사용자 이관 요청에 따라 적용했다. 메뉴·구역노트·외부 공유 화면은 PWA 1.0.83에 포함한다. Android Beta 1.19는 이번 릴리스에서 변경하지 않는다.

현 회사 전용 설치에서는 기존 승인 회원을 기본 회사로 연결하고 이후 승인에도 같은 연결을 만든다. 여러 회사에 판매하기 전에는 `quickflex_note_sync_member` 자동 연결 트리거를 교체하고 회사 초대/가입 절차를 넣어야 한다. 클라이언트가 회사 멤버십을 만들거나 권한을 높일 수는 없다. 지정 편집자 배정은 현재 서버 관리 작업이며 UI는 추가하지 않았다.

## 기존 RouteNote 데이터

이관 당시 RouteNote의 사용 중인 구역 35개·팁 138개·사진 70개를 복사했다. 구역 미지정 팁 3개를 위한 보조 구역 1개가 추가되어 36개였다. 이후 사용자 요청으로 팁·사진이 없는 `218`, `222`, `300A`, `300B`를 삭제해 현재 구역은 32개이며 팁·사진 수는 동일하다. 원본과 삭제 전 백업은 보존했으며 상세 기록은 [이관 기록](ROUTENOTE-IMPORT-20260921.md)에 있다.

확인된 이메일로 정확히 계정이 연결된 팁은 31개다. 나머지 107개는 작성자 이름을 보존하고 `created_by=null`로 두어 다른 사용자에게 수정 권한이 넘어가지 않게 했다. 이름만 같은 계정으로 임의 연결하지 않으며, 계정 확인 후 별도 권한 이관이 필요하다. 원본 JSON은 일반 회원에게 공개하지 않는 private archive에 보관한다.

## 기간제 공유

사용자의 배포 승인 후 `20260921114325_route_note_shares.sql`과 `supabase/functions/route-note-share/index.ts`를 운영 서버에 적용했다. `route-share.html`은 PWA 1.0.83에 포함한다. 공유 SQL → `route-note-share` 함수 → PWA 순서로 반영하며, 운영 서버에서 유효한 링크의 구역·팁·서명 사진 열람을 확인했다. `supabase/config.toml`의 해당 함수 `verify_jwt=false`는 로그인 없는 토큰 열람을 위한 설정이며 실제 승인·회사·구역·기간 검증을 서버에서 수행한다.

공유 토큰은 256비트 난수이며 DB에는 해시만 저장한다. 승인된 회사 회원이 링크를 만들 수 있고, 만든 사람만 자신의 링크를 관리한다. 공개 열람은 유효한 토큰으로 지정된 구역과 그 팁·사진만 반환한다. 생성자의 승인이나 회사 멤버십이 해제되어도 열람이 차단된다. 원본 보관 JSON, 내부 계정 ID, 다른 구역 데이터는 공유하지 않는다.

토큰은 URL fragment에 넣고 POST 본문으로 전달한다. 서버 응답은 no-store, 사진 URL은 공유 만료까지 남은 시간과 5분 중 짧은 기간만 유효하다. 만료 시 열린 페이지의 표시도 지운다. 이미 수신한 내용·저장한 파일 자체를 원격 회수하는 기능은 아니다. 이번에는 개인 복사본 저장이나 앱 가입 유도 흐름을 추가하지 않는다.

## 지도와 사진

지도 SDK는 구역노트를 열 때 로드한다. 검색·필터·패널 전환 때 지도 인스턴스를 유지하며, 구역 선택 시 위쪽 검색창과 패널을 제외한 공간에 경계를 맞춘다. 공개 브라우저 client ID는 `ROUTE_NOTES_CONFIG`에 있고 허용 도메인은 Naver Cloud 설정에 따른다. SDK 초기화·렌더 실패 시에도 목록과 텍스트 메모를 계속 쓸 수 있다. GeoJSON의 분리된 영역과 내부 빈 영역 및 검증된 원본 구역 색상을 유지한다. [Naver 지도 시작 안내](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html), [Polygon API](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Polygon.html)를 참고했다.

사진은 JPEG/PNG/WebP, 한 장 5MB까지이며 서명 URL은 5분간 유효하다. 새로 열면 URL을 다시 발급한다. 사진이 있는 팁은 사진을 먼저 개별 삭제해야 한다. SQL도 같은 조건을 강제한다. Storage와 PostgreSQL 사이에는 분산 트랜잭션이 없으므로 업로드 중 계정 변경이나 네트워크 장애로 생긴 private orphan은 향후 서버 정리 작업 대상이며, 클라이언트가 다른 계정의 정리 작업을 계속 실행하지 않는다.

## 2026-09-22 인터뷰 반영: 혼합 경계 편집 (PWA 1.0.86)

- 우편번호로 경계를 불러오고 직접 그린 영역을 같은 구역에 추가한다. 상세 코드 하나에 여러 우편번호를 연결하거나 같은 우편번호를 여러 코드로 나누는 구성을 지원하며, 코드 묶음 수를 네 개로 제한하지 않는다.
- 우편번호로 불러온 경계도 점 이동·추가·삭제, 실행 취소/다시 실행, 원본 우편번호 복원이 가능하다. 원본 GeoJSON의 분리 영역·내부 구멍·subLabels·postcodes·codeGroups·regionName을 보존한다. 그리던 점을 버리고 돌아갈 때는 확인한다.
- 처음에는 구역 이름과 상세 코드·우편번호를 앞세우고 지역 이름·색상·설명은 접어 둔다. 지도 편집 중에는 지도와 편집 도구가 먼저 보인다. 저장 전 묶음 내용을 확인한다.
- 회사 내 다른 구역이 사용 중인 상세 코드의 새 등록을 차단한다. 한 구역 안의 같은 코드를 가진 여러 경계/우편번호는 허용한다. 기존 `302C02 / 03` 같은 축약 표기는 두 코드로 검사한다. DB의 회사+상세코드 고유키로 동시 등록을 막는다.
- 경계가 수정되어 이미 저장한 팁의 위치가 밖에 놓이더라도 기존 글·사진을 삭제/이동하지 않는다. 같은 좌표를 유지한 글 수정은 허용하고 신규/이동 위치만 현재 경계를 검사한다.
- 지도 마커 종류는 원본의 의미별 SVG로 구분한다. 같은 상세코드의 맞닿은 우편번호 경계선은 중복 표시하지 않으며 내부 구멍과 원본 면은 그대로 보존한다.

추가 파일: `src/ui/route-note-zone-editor.js`, `src/lib/route-note-zone-model.js`, `src/lib/route-note-rules.js`, `src/lib/route-note-map-geometry.js`, `styles/route-note-zone-editor.css`.
